# KAI-TEQ V9.4 — Microsoft popup completion fix

This patch fixes the Microsoft 365 popup getting stuck on the KAI-TEQ Dashboard after Entra successfully returns an authorization code.

## Root cause
The app uses `@azure/msal-browser` v5. In v5, popup authentication requires a dedicated redirect bridge page. The existing `msal-popup.html` was only a static message and Vite was not configured to emit it as a separate HTML entry, so Netlify could fall back to the main SPA and load the Dashboard inside the popup.

## Changes
- `msal-popup.html` now runs `broadcastResponseToMainFrame()` from `@azure/msal-browser/redirect-bridge`.
- `vite.config.js` now builds both `index.html` and `msal-popup.html` as separate HTML entries.
- Popup token/login calls opt into MSAL's interaction recovery flag.
- No changes are required to the existing Microsoft Graph permissions or Netlify environment variables.

## Entra redirect URIs
Keep the four SPA URIs already configured:
- https://app.kai-teq.com
- https://app.kai-teq.com/msal-popup.html
- https://kaiteq-app.netlify.app
- https://kaiteq-app.netlify.app/msal-popup.html

After deploying, hard-refresh the app and test Connect once.
